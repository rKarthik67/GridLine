## Title
Start a project — Start blank: create an empty project from a form

### Summary
In "Start blank" mode, the user fills a short form (project name, client, city, state, project type, bid due date) and clicks "Create project" to create a brand-new, empty `Project` + `ProjectVersion 1` with no trades, bidders, or scope — ready to be built up manually on the project's tabs. This is the fast path for estimators who don't have a filled Excel template.

### User story
As an estimator starting a new project from scratch, I want to create a blank project with just a name (and a few optional details), so that I can begin adding trades and scope myself without needing a pre-filled workbook.

### Acceptance criteria
- [ ] Selecting "Start blank" in the segmented control (`aria-pressed` reflects `mode`) replaces the import drop zone with a form (`className="fgrid"`) of six fields: Project name, Client, City, State, Project type (all plain text inputs), and Bid due (a `type="date"` input) — bound to local `form` state, no field is required to have a value except Project name.
- [ ] "Create project" is disabled while `busy` or while `form.projectName` is empty/whitespace; it is enabled as soon as a non-blank project name is typed (no other field is required client-side).
- [ ] Clicking "Create project" posts the form fields as JSON to `POST /api/projects` (`{ projectName, clientName, city, stateCode, projectType, bidDueOn }`; the other `ProjectIn` fields the frontend doesn't expose — `projectNo`, `stage`, `contractType`, `divisionId`, `branchId`, `street`, `countyName`, `postalCode`, `crmRef`, `estimatorId`, `managerId`, `grossArea` — are simply omitted/`null`).
- [ ] On success the modal closes and the app navigates to `/p/{projectNo}/v/{versionNo}/bid-board` for the new project (`onCreated`), and the Portfolio list is refetched so the project appears.
- [ ] A blank/whitespace-only project name is rejected server-side with `400` ("Project name is required.") even if the client-side disabled check were bypassed.
- [ ] A state value that isn't a 2-letter code matching `UsState.StateCode` is rejected with `400` ("'{state}' is not a US state code.").
- [ ] The created project is auto-numbered (`CompanyProfile.ProjectNoPrefix` + next sequence number) since the blank form never supplies a project number; stage defaults to `'lead'`.
- [ ] The created `ProjectVersion 1` is `IsPrimary = true`, `Status = 'active'`, uses the current `CodeEdition` and the first template `RequirementSet`, has default `VersionMarkup` rates seeded (sales-tax rate from the chosen state if any, other markup defaults from `MarkupType`, excluding `precon`/`genreq`), and gets the default `CostKit`/`CostKitItem` lines applied (precon/overhead starter line items) just like the imported-project path.
- [ ] Requires the `project.edit` capability; without it the request is rejected.

### Technical spec
**Frontend:** `web/src/pages/StartProject.tsx`. State: `form` (`{ projectName, clientName, city, stateCode: 'VA', projectType, bidDueOn }`, `stateCode` defaults to `'VA'`). Fields are rendered generically from a tuple array `[['projectName','Project name'], ['clientName','Client'], ['city','City'], ['stateCode','State'], ['projectType','Project type'], ['bidDueOn','Bid due']]`, each an `<input>` bound with `onChange={e => setForm({...form, [k]: e.target.value})}`. `create()` handler: `mode === 'blank' ? await api.post<{ projectNo: string; versionNo: number }>('/projects', form) : ...`. No dedicated response type is declared in `web/src/api/types.ts` for this call; the frontend only reads `projectNo`/`versionNo` off the response.
**Backend:** `POST /api/projects` in `ProjectEndpoints.Map` (`api/src/Gridline.Api/Endpoints/ProjectEndpoints.cs`), bound to `ProjectIn` (all fields nullable: `ProjectName, ProjectNo, Stage, ClientName, ProjectType, ContractType, DivisionId, BranchId, Street, City, StateCode, CountyName, PostalCode, BidDueOn, CrmRef, EstimatorId, ManagerId, GrossArea, RowRev`). Requires capability `project.edit` (`ctx.Me().Require("project.edit")`); validates `ProjectName` is non-blank. Calls the shared `CreateProject(Work w, ProjectIn p, bool withMarkups = true)` helper (bottom of the same file), then `ApplyDefaultCostKits(w, vid)`, then `Recalc.Summary(w, vid, "project.create")` (see Architecture.md: Recalculation engine), logs `w.Log(pid, vid, "project.create", "project", pid, after: { body.ProjectName })`, commits, and returns `201 Created` at `/api/projects/{no}` with body `{ projectId, projectNo, versionNo: 1 }`. `CreateProject` itself: resolves/validates the project number (auto-increments `CompanyProfile.NextProjectNo` when blank, else trims the given number and 409s if taken), validates the state code, inserts `Project`, inserts `ProjectVersion` (VersionNo 1, IsPrimary, Status 'active', current CodeEdition, first template RequirementSet, GrossArea from `p.GrossArea ?? 0`), seeds `VersionMarkup` rows from `MarkupType` (sales-tax rate from `UsState.SalesTaxRate` for the `salestax` code, `DefaultRatePct` otherwise, excluding `precon`/`genreq`) when `withMarkups` (true for this path), syncs `ProjectVersion.FeePct` from the `'fee'` markup row, inserts the creator as `ProjectMember` `'owner'` (plus Estimator/Manager as `'editor'` if given and different from the creator — not reachable from this form since it doesn't expose those fields), and inserts a `RecentProject` row for the creator.
**Database:** Writes `Project` (`ProjectNo UNIQUE`, `Stage ProjectStage` enum defaulting `'lead'`, `StateCode char(2) REFERENCES UsState`, `RowRev int NOT NULL DEFAULT 1`), `ProjectVersion` (`UNIQUE (ProjectId, VersionNo)`, partial unique index `UxOnePrimaryVersion ON ProjectVersion (ProjectId) WHERE IsPrimary` — enforces only one primary version per project), `VersionMarkup` (`PRIMARY KEY (VersionId, MarkupCode)`), `ProjectMember` (`PRIMARY KEY (ProjectId, UserId)`), `RecentProject` (`PRIMARY KEY (UserId, ProjectId)`), and `CostLine` (from `ApplyDefaultCostKits`, one row per active `CostKitItem` under the `IsDefault` `CostKit`, `SortKey` assigned via `row_number() OVER (PARTITION BY k.Area ...)`, with generated columns `ActualTotal`/`QuotedTotal` computed from `Qty * Rate`). Reads `CompanyProfile` (and increments `NextProjectNo`), `UsState`, `CodeEdition` (`WHERE IsCurrent`), `RequirementSet` (`WHERE IsTemplate ORDER BY RequirementSetId LIMIT 1`), `MarkupType`. `TrgTouch` triggers exist on `Project`/`ProjectVersion` but fire only on `UPDATE`, not on these `INSERT`s.

### Dependencies
- Shares `ProjectEndpoints.CreateProject` and `ApplyDefaultCostKits` with `02-import-excel-create-project.md` — the two flows produce the same baseline `Project`/`ProjectVersion`/`VersionMarkup`/`ProjectMember`/`CostLine` shape, differing only in whether trades/bidders/zones/crew/scope are also populated.
- Downstream: the newly created, empty version is what every other project tab (`profile`, `crew-plan`, `precon-services`, `overheads`, `bid-board`, `scope-match`, `base-requirements`, `price-roll-up`) then operates on — out of scope here, documented in their own page folders.
- See `_Overview/Architecture.md`: Unit of work (`Work`/`w.Log`/commit+broadcast), Recalculation engine (`Recalc.Summary`), Authorization/scoping (capability `project.edit`).

### Notes / edge cases
- The frontend's blank-start form is a strict subset of `ProjectIn` — fields like `projectNo`, `stage`, `contractType`, division/branch, street/county/postal, CRM ref, estimator/manager, and gross area can only be set later (e.g. via the Project profile tab's `PATCH /api/projects/{id}`), not from this modal.
- `stateCode` defaults to `'VA'` in the form even though the field is optional server-side; an empty string is sent as `""` not `null`, so check how `CreateProject` treats `string.IsNullOrWhiteSpace(p.StateCode)` (treated as "no state") versus a non-matching 2-letter code (rejected with 400) — clearing the field entirely is safe, typing an invalid code is not.
- Because no trades exist yet, `Recalc.Summary` runs against an empty trade set — the roll-up it writes (`RollupLine`/`RollupZone`, `CalcRun`) will reflect zero trades/budget until trades are added elsewhere.
- Project-number collisions are only possible when a caller supplies one explicitly; this form never does, so in practice every blank-start project is auto-numbered and the 409 branch is unreachable from this UI (relevant to the Portfolio "duplicate" project workflows instead).
- Like the import-create path, the creator is the only `ProjectMember` immediately after creation, so the `project.create` activity/SignalR broadcast has no other tab in the project's group to receive it yet.
