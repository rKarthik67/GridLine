## Title
Project profile — Manage rates, markups and indirect items

### Summary
The Rates & indirects tab shows every markup/rate applied in the price roll-up (reserves, bond & cover, insurance, fee, sales tax) plus the two cost-total switches (project overheads, precon services), each with an on/off toggle, editable rate %, fixed-amount override, and budget amount; below it, a free-form list of indirect items (owner-requested costs like permits or IT) that can be added, edited and deleted. Every change here feeds the Price roll-up and recalculates totals.

### User story
As a project estimator, I want to adjust a version's markup rates, override them with fixed amounts, switch any rate off without losing its value, and add custom indirect cost items so that the price roll-up reflects the deal-specific terms of this bid.

### Acceptance criteria
- [ ] The rates table lists the two cost switches (Project overheads, Precon services — showing only their on/off state and current roll-up amount) and every markup (reserves, bond & cover, insurance, fee, sales tax), each showing name, what it's applied to, rate %, company default rate %, fixed amount, budget amount, and the resulting in-roll-up amount.
- [ ] Switching a rate off via the toggle keeps the typed rate/fixed amount but makes it count as $0 in the roll-up, shown as a "off · $0" tag; switching it back on restores the stored value.
- [ ] Rate % is inline-editable (0–100 inclusive) except when the row is off; editing a fixed amount is inline-editable and clearing it reverts to using the rate (`clearFixed`); budget amount is inline-editable independent of on/off state.
- [ ] The fee row shows a badge with the count of carved-out cost categories when fee carve-outs are active and any carve-outs are selected (see `05-manage-fee-carve-outs.md`).
- [ ] Below the rates table, "Indirect items" lists every custom indirect line with an on/off toggle, inline-editable item name and description, an "in fee base" checkbox (unchecking marks it `outsideFee`), an inline-editable amount, the resulting roll-up amount, and a delete button.
- [ ] "Add indirect item" opens a modal (`IndirectModal`, shared with Bid board) to create a new indirect item; an empty indirect list shows "No indirect items. Add one for owner-requested costs such as permits, IT or testing."
- [ ] Saving an unknown markup code is rejected with "Unknown rate '{code}'." and a rate outside 0–100 is rejected with "Rate for {code} must be between 0 and 100%."
- [ ] Creating an indirect item with a blank name is rejected with "Give the line a name."; editing one to a blank name is rejected with "The line needs a name."
- [ ] All edit/toggle/add/delete controls are disabled when `project.access === 'viewer'` or the version's `status === 'locked'`.
- [ ] Any successful save (rate change or indirect item change) invalidates the markups, price-roll-up and bid-board query caches for this version so every dependent view updates.

### Technical spec
**Frontend:** `web/src/pages/project/Profile.tsx`, component `Rates({ project, version })`, using the shared `OnOff` toggle component. Loads `useQuery({ queryKey: vkey('markups', vid), queryFn: () => api.get<RatesData>(\`/versions/${vid}/markups\`) })` and `useQuery({ queryKey: vkey('price-roll-up', vid), queryFn: () => api.get<RollUpData>(\`/versions/${vid}/price-roll-up\`) })` (amounts for each line come from the roll-up, not the markups call). Saving a rate: `api.put(\`/versions/${vid}/markups\`, [{ code, ...body }])` where `body` is one of `{ isOff }`, `{ ratePct }`, `{ fixedAmount }` or `{ clearFixed: true }`, `{ budgetAmount }`. Saving an indirect item: `api.patch(\`/indirect/${id}\`, body)`. Deleting: `api.del(\`/indirect/${id}\`)`. Adding opens `<IndirectModal versionId={vid} .../>` imported from `project/BidBoard.tsx`, which posts to `POST /api/versions/{id}/indirect`. All refresh via `refresh()` which invalidates `vkey('markups', vid)`, `vkey('price-roll-up', vid)` and `vkey('bid-board', vid)`. Types `RatesData { markups: MarkupRow[]; costs: {...}[] }` and `RollUpData` (with `indirect: IndirectRow[]`) are in `web/src/api/types.ts`.

**Backend** (`ProjectEndpoints.cs` for markups, `SummaryEndpoints.cs` for indirect items/roll-up):
- `GET /api/versions/{id:long}/markups` — `Access.Version(c, ctx.Me(), id)` (default `"viewer"`); returns `{ markups: Markups(c, id), costs: CostSwitches(c, id) }`. `Markups` joins `MarkupType` with `ProjectVersion`/`Project`/`UsState` and `VersionMarkup`, excluding codes `'precon'`/`'genreq'` (those are the `costs` switches instead), defaulting `RatePct` to the sales-tax state rate (for `salestax`) or the markup type's `DefaultRatePct` when no `VersionMarkup` row exists yet.
- `PUT /api/versions/{id:long}/markups` (`List<MarkupPut> { Code, RatePct, FixedAmount, BudgetAmount, ClearFixed, IsOff }`) — `Access.Version(w, id)` (default `"editor"`, 423 if locked). Per item: validates the code exists in `MarkupType` (400 if not) and `RatePct` is 0–100 (400 if not); upserts `VersionMarkup` via `INSERT ... ON CONFLICT (VersionId, MarkupCode) DO UPDATE`, defaulting `RatePct` on insert from the sales-tax state rate or `MarkupType.DefaultRatePct`; `FixedAmount` is cleared when `ClearFixed` is true, else coalesced. When the code is `"fee"` and a `RatePct` was sent, also updates the denormalized `ProjectVersion.FeePct`. Calls `Recalc.Summary(w, id, "markups.update")` (Architecture.md Recalculation engine), logs `"markups.update"`, returns the refreshed markups/costs plus the recalculation hash.
- `GET /api/versions/{id:long}/price-roll-up` — `Access.Version(w, id, "viewer")`; builds the full roll-up via `SummaryEndpoints.Build`, which runs `Recalc.SummaryInput` + `Rules.Summary` (hybrid browser/server calc per Architecture.md), and includes `indirect` (from `IndirectItem`), `markups`, `zoneReserves`, and `carveOuts`.
- `POST /api/versions/{id:long}/indirect` (`IndirectIn { ItemName, Amount, OutsideFee, SortOrder, Description, IsOff }`) — `Access.Version(w, id)` (editor). Rejects blank `ItemName` (400). Inserts into `IndirectItem`, defaulting `SortOrder` to `max(SortOrder)+1` for the version. `Recalc.Summary(w, id, "indirect.create")`, logs `"indirect.create"`, returns the rebuilt roll-up (`Build`).
- `PATCH /api/indirect/{id:long}` — `Access.Indirect(w, id)` (resolves scope from the `IndirectItem` row). Rejects a blank (but non-null) `ItemName`. `UPDATE IndirectItem SET ... coalesce(...)`; `Description` is special-cased: `null` leaves it unchanged, but an empty/whitespace string clears it to `NULL`. `Recalc.Summary(w, s.VersionId, "indirect.update")`.
- `DELETE /api/indirect/{id:long}` — `Access.Indirect(w, id)`; deletes the row, `Recalc.Summary(w, s.VersionId, "indirect.delete")`.

**Database:** Table `VersionMarkup` (`001_init.sql` + `IsOff` added in `007_fee_carveouts.sql`): `VersionId (FK ProjectVersion ON DELETE CASCADE), MarkupCode (FK MarkupType), RatePct, FixedAmount, BudgetAmount, IsOff`, `PRIMARY KEY (VersionId, MarkupCode)`. Table `MarkupType` (reference data) supplies `MarkupName, AppliesTo, SortOrder, DefaultRatePct`. Table `IndirectItem` (`001_init.sql` + `Description`/`IsOff` added in `007_fee_carveouts.sql`): `IndirectId, VersionId (FK ProjectVersion ON DELETE CASCADE), ItemName, Amount, OutsideFee, SortOrder, Description, IsOff`. `ProjectVersion.FeePct` is updated redundantly alongside `VersionMarkup`'s `fee` row whenever the fee rate changes (denormalized copy used elsewhere, e.g. version list display).

### Dependencies
- See `_Overview/Architecture.md`: Recalculation engine (`Recalc.Summary`, hybrid client/server calc + `CalcRun` mismatch detection), Authorization/scoping (locked-version 423).
- Directly feeds `RollUpData` consumed by the Price roll-up page (`PriceRollUp.md`) and the Bid board's indirect totals.
- `05-manage-fee-carve-outs.md` reads/writes the same `price-roll-up` cache and the fee rate; both tabs invalidate each other's queries on save.
- `IndirectModal` (add-item UI) is shared with `BidBoard.md` — changing its fields affects both pages.

### Notes / edge cases
- "Off" does not delete or zero the stored rate/amount — it is a separate `IsOff` boolean so the typed value survives being switched off and back on; a developer must not conflate "off" with "rate = 0".
- The company-default rate (`defaultRatePct`) shown read-only alongside the editable rate is computed fresh each read (sales tax from `UsState.SalesTaxRate` keyed by the project's `StateCode`, everything else from `MarkupType.DefaultRatePct`) — it is never persisted on `VersionMarkup`, so changing a state's tax rate retroactively changes the "company default" column for every version in that state without needing any migration.
- Updating `ratePct` for the `fee` markup code has a side effect of also writing `ProjectVersion.FeePct` — two different tables store the same number; both are on the write path of this one PUT, and `05-manage-fee-carve-outs.md`'s fee % field writes the same two places via a different endpoint, so keep them in sync if either is changed independently.
- `Markups()` excludes `'precon'` and `'genreq'` entirely — those two codes only ever appear via `CostSwitches()`, so a code search for a markup row with `MarkupCode IN ('precon','genreq')` in the `markups` array will always come up empty.
- `IndirectItem.Description`'s PATCH semantics (`null` = leave alone, `""`/whitespace = clear) differs from most other fields' plain `coalesce` semantics in this same file — easy to miss when reusing this endpoint's pattern elsewhere.
