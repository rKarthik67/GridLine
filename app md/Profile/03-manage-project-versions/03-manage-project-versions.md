## Title
Project profile — Manage, create, lock and compare versions

### Summary
The Versions tab lists every version of a project, lets an editor rename a version's label, mark a version primary, lock/unlock a version, create a new version (optionally copied from an existing one), copy the whole project as a brand-new project, and compare the trade-by-trade and roll-up totals between any two versions. It is the control center for the project's versioning model described in Architecture.md.

### User story
As a project estimator or manager, I want to create new pricing versions, rename and lock them, pick which one is primary, and compare two versions' numbers side by side so that I can iterate on a bid without losing earlier pricing scenarios.

### Acceptance criteria
- [ ] The version table lists every version with its number, "Primary" tag when applicable, an inline-editable label, a status tag (locked = red, submitted = blue, else neutral), gross SF, created date, and row actions.
- [ ] "Open" navigates to that version's bid board; the expand icon opens the same URL in a new browser tab.
- [ ] "Make primary" is shown only when the caller can edit and the version isn't already primary; it flips primary status instantly and refreshes the project query.
- [ ] A "Lock"/"Unlock" button is shown only to users with the `version.lock` capability; clicking it toggles `status` between `locked` and `active` and shows a corresponding toast.
- [ ] "New version" opens a modal to pick a source version to copy from and an optional label; creating one navigates the browser to the new version's profile tab.
- [ ] "Copy as a new project" prompts for a new project name (pre-filled as "{project name} (copy)"), creates a brand-new project + version 1 copied from the currently open version, and navigates to that new project's bid board.
- [ ] The Versions tab text states what copying includes: zones, rates, trades with their bids and scope answers, estimates, indirect items and cost lines — and that the original is never changed.
- [ ] When the project has more than one version, a "Compare versions" panel lets the user pick version A and B via selects; picking the same version for both shows "Pick two different versions." instead of a comparison; otherwise it shows a trade-level diff table (CSI code, trade name, amount in A, amount in B, delta, added/removed/changed/same tag — rows tagged "same" are hidden, and an all-same comparison shows a single explanatory row) and a roll-up line diff table (name, A, B, delta).
- [ ] All edit/create/lock/copy actions are disabled or hidden when `project.access === 'viewer'`; Lock/Unlock additionally requires the `version.lock` capability regardless of access level.
- [ ] A user with only `viewer` access who also happens to have `version.lock` cannot actually unlock/lock (server returns 403 for insufficient rank) even though the button renders — because the UI only hides Lock/Unlock based on capability, not access level, for the unlock path (unlocking is allowed at `viewer` read level to just *view* the check, but the server still enforces `version.lock` requires more than viewer).

### Technical spec
**Frontend:** `web/src/pages/project/Profile.tsx`, component `Versions({ project, version })`. Reads `project.versions` from the shared `ProjectDetail`. Inline label edit uses `<EditCell>` → `api.patch(\`/versions/${v.versionId}\`, { versionLabel: x })`. Lock/unlock: `api.patch(\`/versions/${v.versionId}\`, { status: v.status === 'locked' ? 'active' : 'locked' })`, gated by `useAuth().can('version.lock')`. Make primary: `api.post(\`/versions/${v.versionId}/primary\`)`. New version modal (`NewVersion` component): `api.post<{ versionNo: number }>(\`/projects/${project.projectId}/versions\`, { fromVersionId, versionLabel })`. Copy project: `api.post<{ projectNo: string }>(\`/projects/${project.projectId}/copy\`, { versionId: version.versionId, projectName: name })`. Compare: `useQuery({ queryKey: ['compare', a, b], queryFn: () => api.get(\`/versions/compare?a=${a}&b=${b}\`), enabled: !!a && !!b && a !== b })` returning `{ trades: {...}[]; summary: {...}[] }`. All mutating calls route through `useAction()`'s `run()` for busy-state + toast, and `refresh()` invalidates `['project', project.projectNo]`.

**Backend** (`ProjectEndpoints.cs`):
- `GET /api/projects/{id:long}/versions` — `Access.Project(c, null, ctx.Me(), id, "viewer")`; returns `VersionRow[]` via the shared `VersionCols` projection.
- `POST /api/projects/{id:long}/versions` (`NewVersionIn { FromVersionId, VersionLabel }`) — `Access.Project(w, id, "editor")`. Resolves the source version (defaults to the project's current primary version if `FromVersionId` is omitted), validates it belongs to the same project. Computes the next `VersionNo` (`max+1`), inserts a new `ProjectVersion` row copying `EditionId, RequirementSetId, GrossArea, BuildMonths, FeePct, BaselineName` from the source and setting `IsPrimary = false, Status = 'draft'`, then `Versions.CopyContent(w, from, vid)` duplicates the version's trades/bids/scope/estimates/indirect items/cost lines, then `Recalc.Summary(w, vid, "version.create")`, logs `"version.create"`.
- `PATCH /api/versions/{id:long}` (`VersionPatch { VersionLabel, Status, GrossArea, BuildMonths, FeePct, BaselineName }`) — access need depends on the request: unlocking (`Status` present and not `"locked"`) only requires `"viewer"` rank to *read* the scope, but if `unlocking || body.Status == "locked"` the endpoint then calls `w.User.Require("version.lock")` and throws 403 if the resolved `s.Access == "viewer"`; all other patches require `"editor"`. Validates `Status` is one of `draft/active/submitted/locked`. Runs `UPDATE ProjectVersion SET VersionLabel = coalesce(...), Status = coalesce(...), GrossArea = coalesce(...), ZonesSetArea = CASE WHEN GrossArea supplied THEN false ELSE ZonesSetArea END, BuildMonths, FeePct, BaselineName (only replaced when SetBaseline), ChangedBy`. If `BaselineName` changed, calls `Budgets.ApplyBaseline(w, id)`; if `GrossArea` or `BaselineName` changed, calls `Recalc.Version(w, id, "version.update")`. Logs verb `version.{status}` when status changed else `"version.update"`.
- `POST /api/versions/{id:long}/primary` — `Access.Version(w, id, "viewer")` then explicitly rejects `viewer` access with 403; clears any existing primary for the project (`UPDATE ProjectVersion SET IsPrimary = false WHERE ProjectId = @p AND IsPrimary`) then sets the target version primary; logs `"version.primary"`.
- `GET /api/versions/compare?a&b` — resolves both versions' scopes via `Access.Version`, requires they belong to the same project (400 otherwise). Trade diff via a `FULL JOIN` of `Trade` CTEs per version (`coalesce(CarriedValue, LowestValue)`), classified `added/removed/changed/same`. Summary diff via `FULL JOIN` of `RollupLine` rows by `LineName`. Read-only (`Work` opened but never committed).
- `POST /api/projects/{id:long}/copy` (`CopyProjectIn { VersionId, ProjectName }`) — requires capability `project.edit`. Validates the source version belongs to the given project id. Loads the project's address/client fields, overrides name (defaults to "{name} (copy)") and resets `Stage` to `'lead'`, calls `ProjectEndpoints.CreateProject(w, p, withMarkups: false)` to create the new Project + Version 1, then `Versions.CopyContent(w, body.VersionId, vid)`, then `Recalc.Version(w, vid, "project.copy")`, logs `"project.copy"`.

**Database:** Table `ProjectVersion` (`001_init.sql`): `VersionId, ProjectId (FK Project ON DELETE CASCADE), VersionNo, VersionLabel, IsPrimary, Status (CHECK IN ('draft','active','submitted','locked')), CopiedFromVersionId (self-FK), EditionId, RequirementSetId, GrossArea, BuildMonths, FeePct, BaselineName, ReadinessPct, CalcVersion, TotalsHash, RowRev`. Constraints/indexes: `UNIQUE (ProjectId, VersionNo)`, unique index `UxOnePrimaryVersion ON ProjectVersion (ProjectId) WHERE IsPrimary` (DB-enforced single-primary invariant, backing the make-primary two-step UPDATE). Trigger `TrgTouch` (function `TouchRow()`) is attached to `ProjectVersion` (and `Project`), bumping `RowRev`/`ChangedAt` on every `UPDATE` — but unlike the Details tab's `PATCH /projects/{id}`, this endpoint's `VersionPatch` DTO carries no `RowRev` field, so there is no optimistic-concurrency clash check on version edits. Compare reads `Trade` (`CsiCode, TradeName, CarriedValue, LowestValue, ArchivedAt`) and `RollupLine` (`LineName, Amount, SortOrder, VersionId`).

### Dependencies
- See `_Overview/Architecture.md`: Authorization/scoping (locked-version semantics, `version.lock` capability), Versioning model (`IsPrimary`, `Status`), Recalculation engine (`Recalc.Version`/`Recalc.Summary`), Unit of work.
- `Versions.CopyContent` is shared with both "new version" and "copy project" — any ticket that changes what a version contains (zones, rates, trades, scope, estimates, indirect items, cost lines) should note it's duplicated by this routine.
- Version `status === 'locked'` is the gate checked by nearly every other edit ticket on this page (Zones, Rates, Fee carve-outs) via `canEdit = ... && version.status !== 'locked'`.
- `02-manage-zones.md`, `04-manage-rates-and-indirect-items.md`, `05-manage-fee-carve-outs.md` all depend on this ticket's lock state.

### Notes / edge cases
- Unlocking a version is intentionally reachable even by a caller whose resolved scope is `"viewer"` for the *read* check — the actual enforcement is the subsequent `w.User.Require("version.lock")` + explicit `s.Access == "viewer"` throw; don't assume the first `Access.Version(w, id, "viewer")` call is the real permission gate for this endpoint.
- `GrossArea` passed via `PATCH /versions/{id}` silently turns off `ZonesSetArea` (`CASE WHEN @GrossArea::int IS NOT NULL THEN false ELSE ZonesSetArea END`) — editing gross area directly here overrides zone-derived area without an explicit toggle, which can surprise a user who later opens the Zones tab and finds "zones equal total project area" unchecked.
- Making a version primary is two separate `UPDATE` statements in the same transaction (not a single atomic swap) — relies on `Work`'s transaction wrapper, not a DB-level upsert, to stay consistent with `UxOnePrimaryVersion`.
- Compare is computed live from `Trade`/`RollupLine` and is never cached beyond the TanStack Query client cache — it reflects whatever each version's last recalculation produced, not a live recalculation of both versions.
- "Copy as a new project" requires the `project.edit` capability (checked via `Require`), independent of the current project's `access` level — a user who is only an `editor` on this project but lacks the global `project.edit` capability will get a 403 even though the button is visible (visibility only checks `project.access !== 'viewer'`).
