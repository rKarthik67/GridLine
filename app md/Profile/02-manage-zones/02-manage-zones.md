## Title
Project profile — Manage zones (breakout areas)

### Summary
The Zones tab lets an editor define the version's breakout areas (zones) used to split pricing by building, phase or site — each zone has an area/unit, a quantity/unit, a default % share, an optional per-zone reserve override, an "include in total" flag, and at most one "remainder of base bid" zone. The tab also controls version-wide area settings (primary unit of area/quantity, and whether gross area is computed from the zones or entered by hand). Saving recalculates the whole version's prices.

### User story
As a project estimator, I want to add, reorder, and configure the zones a version is broken into (with their areas, units, default splits and reserves) so that Scope match, the bid board and the price roll-up can price and report by zone.

### Acceptance criteria
- [ ] The zone table loads existing zones, each editable in place: color swatch, code (upper-cased), name, floor area, area unit, quantity, unit of quantity, "include in total area" checkbox, "is remainder" radio (only one zone can be selected as remainder across the whole table), default % share, and an expandable row for per-zone reserve % (project/design/escalation).
- [ ] Rows can be dragged to reorder (report order); Up/Down buttons and a Remove button are also available per row when editing is allowed.
- [ ] "Add zone" appends a new blank row (new zones get a client-generated negative placeholder id until saved).
- [ ] The summary strip shows: total area size (either computed from included zones when "zones equal total project area" is on, or hand-entered), primary unit of area (SF/RSF/GSF/USF) select, primary unit of quantity select (N/A, Unit, MW, Key, Space), and the total units count (zones whose unit matches the primary unit, summed) — showing "pick a primary unit" when the primary unit is N/A.
- [ ] The footer row totals included zones' area and all zones' unit counts, and flags the summed default-share percentage in an error color when it doesn't sum to ~100%.
- [ ] Saving validates: every zone needs a non-empty code and name; zone codes must be unique (case/whitespace-normalized); at most one zone can be the remainder; area unit must be one of SF/RSF/GSF/USF; unit of quantity must be one of N/A/Unit/MW/Key/Space; floor area and unit count can't be negative; each reserve % must be between 0 and 100 inclusive — any violation returns a 400 with a specific message and blocks the save.
- [ ] Zones removed from the table (vs. the loaded set) are deleted on save; zones present are updated or inserted.
- [ ] On successful save, a "Zones saved · prices recalculated" confirmation appears and every cached query for this version (any key containing `"v{versionId}"`) plus the `project` query are invalidated.
- [ ] All controls are disabled when `project.access === 'viewer'` or the version's `status === 'locked'`.
- [ ] While loading, the tab shows a "Loading zones" state instead of an empty table.

### Technical spec
**Frontend:** `web/src/pages/project/Profile.tsx`, component `Zones({ project, version })`. Loads with `useQuery({ queryKey: vkey('zones', vid), queryFn: () => api.get<Zone[]>(\`/versions/${vid}/zones\`) })`; local editable copy kept in `rows` state, re-seeded whenever the query data changes. Version-level settings (`zonesSetArea`, `primaryAreaUnit`, `primaryUnitLabel`, `grossArea`) are mirrored into local state `vs`, reset on `version.rowRev`/`grossArea`/`zonesSetArea`/`primaryAreaUnit`/`primaryUnitLabel` change. Save: `api.put<Zone[]>(\`/versions/${vid}/zones\`, { zones: rows, zonesSetArea, primaryAreaUnit, primaryUnitLabel, grossArea: zonesSetArea ? null : grossArea })`; on success invalidates every query whose key stringifies to include `"v{vid}"`, plus the `project` key. Reads `Zone`/`AreaUnit`/`UnitLabel` shapes from `web/src/api/types.ts`.

**Backend:** `GET /api/versions/{id:long}/zones` (`Access.Version(c, ctx.Me(), id)`, default need `"editor"` is not forced here — read uses default `"viewer"` per the two-arg overload) returns the zone list via `ProjectEndpoints.Zones(c, versionId)`. `PUT /api/versions/{id:long}/zones` (`ProjectEndpoints.Map`): `Access.Version(w, id)` (default need `"editor"`, 423 if locked per Architecture.md Authorization/scoping). Validates the rules listed in Acceptance criteria (each a `400 ApiException.Bad`). Deletes zones no longer present (`DELETE FROM Zone WHERE VersionId = @id AND NOT (ZoneId = ANY(@keep))`), neutralizes codes/remainder flag first to avoid unique-index collisions while swapping (`UPDATE Zone SET ZoneCode = '~' || ZoneId, IsRemainder = false`), then per zone either `UPDATE Zone SET ... WHERE ZoneId = @zid AND VersionId = @id` or `INSERT INTO Zone (...) RETURNING ZoneId` followed by `ScopeSetup.AddZoneLineToTrades(w, id, newId)` for brand-new zones. Keeps `ScopeLine.LineText`/`SortKey` in sync with the zone's name/order (`UPDATE ScopeLine l SET LineText = z.ZoneName, SortKey = z.SortOrder FROM Zone z WHERE l.ZoneId = z.ZoneId ...`). Updates `ProjectVersion` (`ZonesSetArea`, `PrimaryAreaUnit`, `PrimaryUnitLabel`, `GrossArea` when not zones-set). Calls `ProjectEndpoints.SyncZoneTotals(w, id)` (recomputes `ProjectVersion.GrossArea`/`TotalUnits` from the zones) then `Recalc.Version(w, id, "zones.update")` (see Architecture.md Recalculation engine), logs `"zones.update"`, commits, returns the refreshed zone list.

**Database:** Table `Zone` (`001_init.sql` + `006_zones.sql`): `ZoneId, VersionId (FK ProjectVersion ON DELETE CASCADE), ZoneCode, ZoneName, SortOrder, FloorArea, UnitCount, UnitLabel, DefaultShare, Colour, AreaUnit, IsRemainder, ExcludeFromTotal, ProjectReservePct, DesignReservePct, EscalationReservePct`. Constraints: `UNIQUE (VersionId, ZoneCode)`, `ZoneAreaUnitCheck CHECK (AreaUnit IN ('SF','RSF','GSF','USF'))`, `ZoneUnitLabelCheck CHECK (UnitLabel IN ('N/A','Unit','MW','Key','Space'))`, unique index `UxZoneRemainder ON Zone (VersionId) WHERE IsRemainder` (enforces at most one remainder zone per version at the DB level too). `ProjectVersion` columns touched: `ZonesSetArea, PrimaryAreaUnit, PrimaryUnitLabel, GrossArea, TotalUnits, ChangedBy`. `ScopeLine.LineText`/`SortKey` updated for rows tied to a zone (`ScopeLine.ZoneId FK Zone ON DELETE CASCADE`), so deleting a zone cascades to delete its `ScopeLine` rows.

### Dependencies
- See `_Overview/Architecture.md`: Authorization/scoping (locked-version 423), Recalculation engine (`Recalc.Version`), Unit of work (commit + `changed` broadcast).
- Feeds Bid board/Scope match zone splits (`Trade`/`ScopeLine` per-zone pricing) — documented in `BidBoard.md`/`ScopeMatch.md`.
- Related: `ScopeSetup.AddZoneLineToTrades` (adds a scope line per existing trade when a new zone is created) — cross-cutting with Scope match tickets.

### Notes / edge cases
- Swapping two zone codes (e.g. renaming A↔B) works only because the server first "parks" every zone's code to `'~' || ZoneId` and clears `IsRemainder` before re-applying — removing that two-step would trip the `UNIQUE (VersionId, ZoneCode)` and `UxZoneRemainder` constraints mid-update.
- `GrossArea` and `TotalUnits` on `ProjectVersion` are derived/denormalized: `SyncZoneTotals` recomputes them from `Zone` rows every save; don't hand-edit them elsewhere without recomputing via this function or they'll drift from the zones.
- When `zonesSetArea` is true, the PUT body sends `grossArea: null` — the server's `coalesce` means the existing `GrossArea` column is left as-is by the raw `UPDATE`, but `SyncZoneTotals` immediately overwrites it from the zone sum afterward, so the effective value is always correct even though the two statements look contradictory in isolation.
- The remainder zone's dollar amount is not stored here — it's computed downstream (bid total minus other zones) wherever zone splits are priced; this ticket only persists the `IsRemainder` flag.
- Deleting a zone cascades to delete any `ScopeLine` rows tied to it (`ON DELETE CASCADE`), which silently removes scope-match answers tied to that zone for every trade.
